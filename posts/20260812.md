# Explicit design gates substantial coding


The complete cell-system design converged at `8949e01a`. The operator chose a
staged realization rather than implementing the full architecture immediately:
Working Coding Cell 0.1 is the next bounded milestone, planned in Pi event 77 as
one local, operator-supervised path from admitted issue and design to a verified,
manually applicable patch closure.


The experience leading to that plan exposed a second load-bearing decision. Case-3
implementation repeatedly made architecture decisions while trying to write code:
Alpha capability, Beta visibility, issue admission, subject custody, methodology,
and evidence semantics moved together. Sigma's design confusion was therefore not
an isolated execution failure; it showed that coding had started without one stable
design artifact defining what the issue was allowed to become.


For substantial or cross-cutting work, design is now an explicit input to the coding
cell, not something Coding Alpha may invent while implementing. Collapsing issue
interpretation, architecture choice, and code production into one seat prevents Beta
from distinguishing faithful implementation from silent redesign and lets newly
discovered scope enter without authority.


The target flow is:


`Issue -> Design cell -> accepted DesignArtifact + receipt -> Planning -> Coding cell`


The design cell consumes the admitted issue, a pinned subject snapshot, and design /
architecture methodology. Its Alpha drafts the design; its Beta falsifies it against
the issue, repository reality, constraints, impact graph, and proof obligations. An
accepted design binds the issue and subject digests. The coding cell receives that
same issue, accepted design, and same or explicitly revalidated subject snapshot.


Coding Alpha retains freedom over local algorithms, helper structure, and other
implementation details inside the design. It may not change scope, public boundaries,
authority, invariants, or non-goals. If implementation reveals a necessary impact,
contradiction, or missing architectural decision, the cell closes nonaccepting with a
contract finding / `needs_recontract`; it may propose a correction but cannot amend
its own authority and continue.


Design must never be implicit. Every coding contract declares one disposition:


- `separate` — substantial or cross-cutting work requires an accepted design-cell
  output and receipt;
- `inline` — a small issue carries a sufficient design capsule defining its boundary;
- `waived` — genuinely local or mechanical work has an explicit operator-authorized
  waiver.


This decision does not insert design-cell implementation ahead of WCC 0.1. The
bootstrap coding cell will require issue plus design supplied through the current
operator/Pi/Sigma process. Once the coding cell works, it can implement the design
cell, followed by the planning and measurement/cohering cells. The architecture is
therefore preserved without making the bootstrap depend on the entire future loop.
